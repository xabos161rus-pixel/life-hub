# LifeHearth AI — план разработки чат-платформы

Документ решений. Читается перед каждым этапом. Ветка: `claude/ai-api-platform-idea-ywbu3m`

---

## 0. Главное решение: зачем это вообще

Прямо: если строить «ещё один красивый клиент к Claude» — проект не нужен. Подписка Max уже даёт Opus без счётчика, а своя платформа даст то же самое, но платно по токенам и беднее.

**Единственное, чего не может ни Max, ни LibreChat, ни Msty, ни один конкурент в мире: ИИ с доступом к твоим собственным данным.** Задачи, цели, привычки, заметки, расходы, обучение, RTE — всё это уже лежит в Dexie на твоих устройствах.

- «Разбери мои расходы за июль и скажи, где течёт»
- «Собери план под цель Х из моих задач»
- «Что у меня в заметках по RTE про поставщика»
- «Посмотри мои привычки за месяц — что просело»

Это не поздняя фича. **Это оправдание всего проекта, и оно входит в MVP.** Если убрать доступ к данным — строить не стоит, лучше пользоваться Max.

## 1. Фундамент

Строим **не отдельное приложение**, а раздел внутри работающего LifeHearth. Причина: 80% сложного уже готово и проверено в бою.

| Что нужно платформе | Статус |
|---|---|
| React 19 + TS + Vite 8 + Tailwind 4 | ✅ есть |
| Доступ с iPhone | ✅ PWA из Safari, без App Store и без $99/год Apple |
| Хранилище истории | ✅ Dexie/IndexedDB + слой `repo.ts` |
| Бэкенд | ✅ Cloudflare Worker + D1 |
| Синхронизация устройств | ✅ E2E-шифрованная, сопряжение по QR |
| Рендер markdown | ✅ `marked` + `dompurify` в зависимостях |
| UI-кит и токены | ✅ `components/ui/*`, OKLCH-палитра |
| Референс чат-интерфейса | ✅ семейный чат на Durable Object |
| Деплой | ✅ push → GitHub Actions → Pages (~2 мин) |

Писать с нуля: слой провайдеров, прокси в Worker, экран чата, инструменты доступа к данным.

### Словарь имён — зафиксирован до первой строки кода

Критика вскрыла, что параллельные проектные наработки использовали разные имена одних и тех же сущностей. Фиксируем один вариант, остальные считаем недействительными:

- Таблицы: `llmChats`, `llmMessages` (не `aiChats`/`aiMessages`)
- Поле текста: `content` (не `text`)
- Схема: Dexie `version(10)`, `SCHEMA_VERSION = 10`
- Ключи провайдеров: **только в секретах Worker**. На устройстве не храним вообще
- Стрим: React-состояние + одна финальная запись в Dexie
- Worker: passthrough SSE, парсинг формата на клиенте

## 2. Этап 0 — фундамент и защита существующих данных

**Это делается до единой строчки чата.** Здесь есть находка, которая важнее всего проекта.

### 2.1. Баг в синхронизации — чинится первым

При разборе кода найден **реальный дефект в работающем приложении**: `src/lib/sync.ts:157-168, 213`.

```ts
// СЕЙЧАС (баг):
let maxUpdatedAt = c.lastPushAt;
for (const name of SYNCED_TABLES) {
  const rows = (await db.table(name).toArray()).filter(r => r.updatedAt > c.lastPushAt);
  for (const row of rows) if (row.updatedAt > maxUpdatedAt) maxUpdatedAt = row.updatedAt;
}
await patchSyncConfig({ lastPushAt: maxUpdatedAt });  // ← курсор до МАКСИМУМА найденного
```

Сценарий потери: таблица `tasks` просканирована в t0. Ты правишь задачу в t0+50мс. В t0+200мс сканируется другая таблица и находит запись с меткой t0+100мс. Курсор уезжает на t0+100. На следующем цикле фильтр `updatedAt > lastPushAt` задачу с t0+50 **не вернёт никогда** — она не уедет в облако, пока её не отредактируют заново.

Сейчас окно узкое (скан — миллисекунды), но дефект настоящий и от объёма данных растёт.

```ts
// ИСПРАВЛЕНИЕ:
const cutoff = new Date().toISOString();   // снимаем ДО скана
// фильтр: r.updatedAt > c.lastPushAt && r.updatedAt <= cutoff
await patchSyncConfig({ lastPushAt: cutoff });
```

### 2.2. Остальная защита данных

- **`try/catch` вокруг применения входящей записи** в `pullPage` (`sync.ts:129-136`). Сейчас одна нерасшифрованная запись роняет синк **всего приложения** навсегда — курсор не двигается, задачи с телефона перестают приходить на мак
- **Составной курсор `(updated_at, id)`** в pull. Сейчас `WHERE updated_at > ?` теряет записи с одинаковой миллисекундной меткой на границе страницы
- **Кнопка сброса курсоров** в `SyncSection` — страховка от рассинхрона
- **Кнопка «скопировать accountId»** — понадобится для allowlist Worker
- **Версия сборки в Настройках** — чтобы отличать баг от старого кэша Service Worker

### 2.3. Инфраструктура разработки

- **Фича-флаг раздела ИИ** в `settings` — скрыт, пока не доведён. Единственное, что делает безопасным мерж недоделанного в `main` рабочего приложения
- **Регресс-чеклист**: Сегодня / Задачи / Заметки / Семья-чат / Фокус — прогонять при любом коммите, трогающем `db.ts`, `sync.ts`, `index.css`
- **Заглушка-эхо в Worker**: возвращает фиксированный текст с реалистичным usage. Позволяет довести весь тракт «отправил → увидел ответ → увидел цену» **не дожидаясь регистрации у провайдера**

> Критика справедливо указала: этап 0 в первоначальном виде был единственным местом, где прогресс зависел от внешних регистраций и не давал ничего на экране. Заглушка-эхо разрывает эту зависимость.

**Сделано, когда:** синк починен, регресс-чеклист зелёный, раздел ИИ есть за флагом и отвечает эхом.

## 3. Деньги — честная смета

Первоначальная оценка «500-1000 ₽ хватит на месяцы» **занижена в 10-30 раз**. Реальный расчёт на ценах Opus 5 ($5 вход / $25 выход за 1M):

Диалог на 20 обменов: накопительный вход ≈ 257 000 токенов ($1.29), выход ≈ 46 000 ($1.15). **Одна глубокая сессия ≈ $2.4 ≈ 200 ₽**, с наценкой реселлера 220-250 ₽.

| | Opus 5 | Sonnet 5 | Haiku 4.5 |
|---|---|---|---|
| 500 ₽ хватит на | 2-3 сессии | 5-6 сессий | ~12 сессий |
| Ежедневное использование | 6000-7500 ₽/мес | ~2500 ₽/мес | ~800 ₽/мес |

### Ловушка: токены размышлений

На `claude-opus-5` **мышление включено по умолчанию**, а его вывод по умолчанию скрыт (`display: 'omitted'`). Токены размышлений тарифицируются **как выходные — $25/1M**. В расчёте выше это ~1500 из 2300 выходных токенов, то есть **две трети счёта за выход** уходит на текст, который ты не видишь.

Решения в коде:
- `thinking: {type: 'adaptive', display: 'summarized'}` — размышления видны и объясняют счёт
- В строке под ответом: «размышления N токенов + ответ M токенов» раздельно
- Стартовать с `output_config.effort: 'medium'`, не с дефолтного `high`
- **Не** отправлять `thinking: 'disabled'` — на opus-5 это допустимо только при effort ≤ high, иначе 400

### Следствия для v1

- **Модель по умолчанию — Sonnet 5**, Opus включается осознанно переключателем
- **Счётчик стоимости в рублях — на первом же экране**, не в поздних этапах
- **Spend cap** в панели провайдера **до первого запроса**
- Вводная цена Sonnet 5 ($2/$10 вместо $3/$15) действует **до 31.08.2026** — потом смета вырастет на 50%
- Русский текст токенизируется дороже английского: эвристику показывать со знаком «≈», лимиты на ней не строить

## 4. Технические решения (все с trade-off)

### 4.1. Стрим — в React-состояние, не в Dexie

**Решение:** текст стрима живёт в React-состоянии, в Dexie идёт **одна финальная запись**.

**Почему:** `useLiveQuery` реагирует на любую мутацию таблицы. Запись чанка каждые 500 мс = перечитывание всего чата, пересборка дерева и перерисовка markdown дважды в секунду. На iPhone это гарантированные пропуски кадров — тот самый класс багов, который в проекте уже дважды правили (комментарии в `ChatTab.tsx:486` и `FamilyScreen.tsx:88`).

**Trade-off:** свернул PWA посреди генерации — ответ потерян. Если это будет мешать, персист делается в отдельную **несинкаемую** таблицу `llmDrafts`, на которую нет `useLiveQuery`.

### 4.2. Worker — passthrough, не нормализация

**Решение:** Worker проксирует SSE-поток байт в байт, формат разбирает клиент.

**Почему:** Workers Free даёт 10 мс CPU на инвокацию. `JSON.parse` на каждую дельту + `JSON.stringify` на каждое исходящее событие при ответе на 2000 токенов — это сотни SSE-событий и реальный риск `Error 1102` посреди генерации. Ожидание I/O в лимит не входит, поэтому passthrough проходит спокойно.

**Trade-off:** клиент должен знать формат провайдера. При одном провайдере это один парсер.

### 4.3. Ключи — только в Worker

**Решение:** API-ключ живёт в секретах Cloudflare Worker. На устройстве не хранится.

**Почему:** ключ в IndexedDB рядом с ключами семьи и аккаунта — лишняя поверхность атаки. Плюс BYOK-заголовок `X-AI-Key` потребовал бы правки CORS (см. ниже).

**Ставится через дашборд Cloudflare** (Workers → Settings → Variables → Encrypt), не через `wrangler secret put` — ноль терминала.

### 4.4. CORS — правится обязательно

`worker/src/index.js:14` сейчас: `'Access-Control-Allow-Headers': 'Content-Type, Authorization, X-Account'`.

Любой новый заголовок падает на preflight ещё до кода Worker. Так как ключи мы в браузере не держим, `X-AI-Key` не нужен — но формат ответа надо передавать **первым SSE-событием** `{t:'meta', format:'anthropic'}`, а не заголовком, иначе понадобится `Access-Control-Expose-Headers`.

### 4.5. max_tokens — 32000, не 4096

При включённом adaptive thinking `max_tokens` — общий потолок на размышления **и** текст. При 4096 ответ будет регулярно обрываться на середине со `stop_reason: 'max_tokens'`, а иногда приходить пустым.

Обрабатывать в UI: `max_tokens` → «ответ обрезан, продолжить?», а не молча `done`.

### 4.6. Отказы модели

`stop_reason: 'refusal'` приходит как HTTP 200 с пустым content. Без обработки это пустой пузырь со статусом «готово».

Актуально: вопросы по RTE (тактическое снаряжение, плитники) могут попадать под классификатор. Показывать «модель отклонила запрос» с категорией, а не пустоту.

### 4.7. История в v1 не синхронизируется

**Решение:** `llmChats`/`llmMessages` **не** в `SYNCED_TABLES` и **не** в бэкапе. Чат живёт на устройстве, страховка — экспорт диалога в markdown.

**Почему:** `pullPage` молча пропускает записи неизвестной таблицы (`if (!isSynced(r.table)) continue`), а курсор после этого двигается — устройство со старой сборкой **навсегда теряет часть переписки**. Плюс полный скан при каждом цикле синка, раздувание бэкапа, конфликты LWW, правки `TrashPage` и `SearchPage`.

**Trade-off:** начал на маке — на телефоне этого диалога нет. Синхронизация вернётся в v2, когда станет ясно, что фича используется ежедневно. Это осознанный размен риска на скорость.

## 5. Дизайн — язык Claude Code

### Решение: локальный акцент, без глобальной перетонировки

Раздел ИИ получает клай-акцент **через inline-переменные на обёртке** — приём, который в проекте уже работает (`--focus-accent` внутри `FocusPage`).

**Что отвергнуто:** глобальная перетонировка нейтралей проекта (hue 283 → 106). Это регресс-риск на всех 20+ экранах ежедневного инструмента ради эстетики одного раздела, которого пока нет. Плюс аврора осталась бы сине-фиолетовой на тёплом сером — ровно тот класс багов с «красными выпуклыми углами», который в проекте правили дважды.

### Токены раздела

```css
.cc-theme {
  --cc-accent-ink:   oklch(67.2% 0.131 38.8);   /* клай Claude ≈ #D97757 */
  --cc-clay-shimmer: oklch(77.0% 0.101 43.6);
  --cc-code-bg:      oklch(15.9% 0 0);
  --cc-border-strong:    oklch(100% 0 0 / 0.20);
  --cc-fill-ghost-hover: oklch(100% 0 0 / 0.05);
  --cc-fill-control:     oklch(100% 0 0 / 0.10);

  --cc-radius:     0.625rem;
  --cc-radius-sm:  0.375rem;
  --cc-marker-col: 1.25rem;
  --cc-touch:      2.6rem;      /* тач-таргет — крупнее, чем в CLI */

  --cc-text-caption: 0.706rem;
  --cc-text-meta:    0.765rem;
  --cc-text-tool:    0.824rem;
  --cc-text-body:    0.941rem;

  --cc-dur-fast: 60ms;  --cc-dur-snap: 120ms;  --cc-dur-base: 200ms;
  --cc-ease-out:  cubic-bezier(0.165, 0.84, 0.44, 1);
  --cc-ease-snap: cubic-bezier(0.32, 0.72, 0, 1);
}
```

Светлая тема — те же имена с пересчитанной светлотой.

### Принципы

- **Асимметрия.** Сообщение пользователя — пузырь справа. Ответ ассистента — **не пузырь**, а поток на всю ширину с маркером-точкой в CSS-grid. Это узнаваемая черта Claude Code
- **Ноль вебшрифтов.** Sans — существующий системный стек. Mono — `ui-monospace` (на iOS/macOS это SF Mono)
- **Моно только на машинном слое** — код, метаданные, счётчики. Тело ответа — обычный текст. В CLI всё моно, но на телефоне это нечитаемо: первое осознанное улучшение относительно оригинала
- **Тач-таргеты 2.6rem** вместо CLI-плотности — второе улучшение
- Иконки lucide, `stroke-width: 1.75` как во всём проекте

**Не переопределять `font-size` полей ввода** — правило `input, textarea { font-size: 16px }` в `index.css:172` лежит вне слоёв и бьёт Tailwind-утилиты по каскаду. Меньше 16px → iOS зумит страницу при фокусе.

**Тени писать формой `shadow-[var(--shadow-accent)]`** — bare-классы вида `shadow-accent` в Tailwind 4 не дают box-shadow (в проекте это уже молча сломано в трёх местах).

## 6. Этапы работ

Каждый этап заканчивается смердженным работающим состоянием, которое можно потрогать на маке и на iPhone.

### Этап 1 — тракт целиком на заглушке
Схема Dexie v10 (`llmChats`, `llmMessages`), экран чата, ввод, рендер markdown, эндпоинт `/ai/chat` с эхо-заглушкой.
**Сделано, когда:** отправил сообщение → увидел ответ → увидел «цену» → перезапустил приложение → история на месте. Без единого рубля и без регистраций.

### Этап 2 — живой провайдер и стриминг
Один адаптер (Polza.ai, ~6% наценки, 400+ моделей, рубли), passthrough SSE, парсер на клиенте, отмена генерации, обработка ошибок (401/403/429/refusal/max_tokens), счётчик стоимости в рублях, spend cap.
**Сделано, когда:** ответ печатается по токенам, стоп работает, стоимость видна, лимит срабатывает.

### Этап 3 — доступ к своим данным ⭐
**Ядро проекта.** Инструменты чтения Dexie: задачи, заметки, расходы, привычки, цели, обучение. Модель вызывает их через tool use и отвечает по твоим реальным данным.
**Сделано, когда:** «разбери мои расходы за месяц» даёт осмысленный ответ по фактическим записям.

### Этап 4 — работа с диалогами
Список чатов, авто-заголовки, переименование, удаление, поиск по своим чатам, экспорт в markdown, обрезка контекста, выбор модели, системный промпт.

### Этап 5 — отделка
Полировка дизайна под Claude Code, «перегенерировать» (= удалить прошлый ответ + создать новый, линейная история), горячие клавиши, микроанимации, пустые состояния.

### Этап 6+ — по факту использования
Синхронизация истории между устройствами, второй провайдер, вложения, RAG по заметкам. **Только после того, как станет ясно, что первым пяти этапам ты реально пользуешься.**

## 7. Что осознанно выкинуто из v1

| Выкинуто | Причина |
|---|---|
| **Crew Mode** | Самая дорогая часть; тянет оркестратор, N параллельных запросов, колонки, семантику выбора победителя, умножение счёта. «Перегенерировать другой моделью» закрывает 80% смысла |
| **Дерево ветвлений** | Пять взаимозависимых инвариантов без единого теста. Симптом бага — не падение, а молча пропавшая часть диалога. Заменяется на «удалить + создать» за ~10% работы |
| **Artifacts** | Самая опасная поверхность рядом с IndexedDB, где лежат ключи семьи и аккаунта. В v1 хватает блока кода с кнопкой «копировать» |
| **Свой highlighter на регулярках** | Украшение, которое сломается на нетривиальном коде и будет выглядеть как баг |
| **Библиотека персон** | Одного поля «системный промпт» достаточно, пока не станет ясно, что роли нужны |
| **GigaChat** | OAuth на порту 9443 — вероятный хард-блокер: fetch из Workers ограничен фиксированным списком портов. Плюс сертификат российского УЦ |
| **4 провайдера с реестром** | При одном провайдере это константа в коде, а не таблица в БД, попадающая в синк |
| **Вложения** | Vision не нужен для твоих задач в первой версии |
| **Prompt caching** | Запись в кэш стоит 1.25× от входа, TTL 5 минут. При паузах больше 5 минут между сообщениями платится премия почти без чтений. Сначала показать `cache_read`/`cache_creation` в интерфейсе и посмотреть на реальный ритм |
| **Глобальная перетонировка палитры** | Регресс-риск на 20+ экранах ради эстетики одного раздела |
| **Двухпанельный режим и шестой таб** | Правка таб-бара меняет вид всех пяти существующих табов. В v1 — один экран, вход из «Ещё» |

## 8. Что настраивается руками — пошагово

1. **Cloudflare Dashboard** → Workers → твой worker → Settings → Variables → **Encrypt** → добавить `AI_PROVIDER_KEY`. Терминал не нужен
2. **Регистрация у провайдера**: [polza.ai](https://polza.ai/) — пополнение от 100 ₽, оплата рублями. Взять API-ключ
3. **Allowlist**: скопировать свой `accountId` кнопкой в Настройках → синхронизация, добавить в переменную `AI_ALLOWED_ACCOUNTS` в том же дашборде. Это единственный барьер между публичным `workers.dev` и твоим платёжным ключом
4. **Spend cap**: выставить лимит в панели провайдера **до первого запроса**
5. **Обновить оба устройства** до одной сборки перед первым запуском чата

## 9. Риски и чем закрываем

| Риск | Как закрыт |
|---|---|

| Утечка ключа | Ключ только в секретах Worker, allowlist по accountId |

## 10. Что осталось неизвестным

Честно — проверится только на практике:

- **Доступ к провайдеру.** Наценки российских агрегаторов (Polza ~6%, RouterAI ~9%, BotHub ~12%, против ProxyAPI ×3.7-4.3 и GPTunnel ×4) взяты из обзорных статей, не из первичных прайсов. Проверять на самом сайте перед пополнением
- **Проходит ли платёж** и не упрётся ли аккаунт в гео-ограничения. Именно поэтому этап 1 не зависит от этого
- **Реальная стоимость месяца** — смета выше расчётная, факт узнается за первую неделю
- **Нужен ли Crew Mode и ветвление** — узнается только после месяца использования базовой версии

## Резюме одним абзацем

Строим раздел ИИ внутри LifeHearth, потому что 80% инфраструктуры уже готово и работает. Первым делом чиним найденный баг синхронизации — он угрожает существующим данным независимо от проекта. Ядро и оправдание проекта — доступ ИИ к личным данным, чего не может ни один конкурент и сама подписка Max. Из первой версии выкинуто всё, что дорого и не проверено спросом: Crew Mode, ветвление, артефакты, вложения, мультипровайдер. Дизайн — язык Claude Code локальным акцентом, без риска для остальных экранов. Смета честная: Sonnet по умолчанию, стоимость в рублях на экране, лимит до первого запроса.
